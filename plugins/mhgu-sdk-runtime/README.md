# MHGU SDK 运行时

Forge 插件由 `mhgu-sdk-runtime` 构建，发布为 `mhgu-sdk.nro`。它提供武器和风格注册、扩展装备箱、武器交易和角色存档服务。Rust 模组通过 [mhgu-sdk](../../crates/mhgu-sdk/README.md) 注册武器与风格。

从仓库根目录运行 `python3 plugins/mhgu-sdk-runtime/package.py`，生成开发安装目录 `plugins/mhgu-sdk-runtime/dist/mhgu-sdk/`。武器整合包由仓库级工具组装，包内的 SDK 目录随附 `arc/frontier/common.arc`。见[整合包构建流程](../../docs/development.md#本地输入和构建)。

游戏只需安装一份 SDK 模组。升级时更新 SDK 和武器模组。武器的固定位置碰撞继续使用 SDK 统一挂接的 GU 碰撞展开入口 `1696FC`。

注册器在 GU `2A79CC` 调用 `27EBBC` 时向当前风格提供已过滤的按键。磁斩锤在这里等待组合键，并在确认普通翻滚或收刀时将按下沿交给原版指令表。对于风格已接管的按键，注册器还会撤销对应的原生收刀和翻滚缓冲，并检查随后到达的动作请求。见[物理手柄输入回放](../magnet-spike/tests/verify_inputs.py)。

SDK 在碰撞展开入口 `16ABAC` 前接收风格提交的独立接触对象，供强化磁冲击等场景命中使用。该入口返回后，SDK 为当前任务猎人的风格派发碰撞查询。磁界弹查询怪物受击形状，打击形态磁力回避在 `16B15C` 结算前查询来袭攻击形状。注册武器也可观察所有本地任务猎人的碰撞通行，用同一受击场景查询怪物出生实例、控制权和受制动作。对应接口见 [MHGU SDK](../../crates/mhgu-sdk/README.md)。

运行时在 GU `17885C` 结算会心后，将同区存活怪物的磁斩锤命中交给怪物控制端的积蓄回调。回调按攻击者的风格匹配，同时支持本地猎人和队友的近战及独立场景命中。控制端通过 `netEmUniqueData` 发布怪物积蓄、耐性及活动束缚资料，接收端按 GU 发送者和怪物控制成员核对同区出生实例。风格的着地请求、确认和中断复用该通道，只有目标怪物控制端能确认。同一控制端也结算队友的磁缚终结与倒地。

磁缚通过 `76AFC` 对本机控制的怪物请求 GU 地面受制动作。运行时在同一次请求的 `A2C04` 中设置计时，原版麻痹自行进入原有初始化。联机时使用 GU 的 `netEmAction`，`1EB1E8` 在 `status_bit` 的高 12 位写入 GU 帧数。`CC154` 只为同一出生实例应用当前控制端发来的受制计时，收到后续动作时清除该计时。GU 转移怪物控制权时保留现有计时。[GroundHold](../../crates/mhgu-sdk/src/combat/collision/hurt/ground_hold.rs) 按出生实例继续查询该动作，当前控制端可释放受制怪物。

## 武器风格

在 MHGU 1.4 的装备箱打开原版「切换风格」页面，原版武器已注册的风格会列在六个原版风格之后。装备扩展武器时，原生页面直接显示它已生效的注册风格与说明。用原版光标选择并确认；取消或退出不会改变已装备风格。选择原版风格会恢复 GU 的动作。超过八项时可左右翻页。

个人状态和队友状态的概要、详情使用实际装备对应的风格名称。队友名称随 GU 的装备资料同步，双方需要加载支持风格资料同步的 SDK，查看方需要安装对应风格。未收到可识别的风格编号时，界面使用 GU 原有名称。

扩展武器的动作和位置事件沿用 GU 的任务包。SDK 从原生装备资料定位接收端的武器插件，原生坐标与插值照常应用。接口见 [MHGU SDK 联机回放](../../crates/mhgu-sdk/src/weapon/style/remote.rs)。

在装备箱登记或覆盖装备组合时，SDK 记录当时的风格。概要和详情显示该组合保存的风格，穿上组合后恢复。原版组合或缺少已记录插件时沿用组合的 GU 原版风格。调换组合时风格随组合移动，删除或覆盖时清除旧记录。斗技场固定装备预览和公会名片历史沿用 GU 记录。

SDK 加载后，按下右摇杆（R3）切换任务锁定目标。左摇杆按下（L3）的地图缩放等操作遵循 GU 当前的操作设置。原版附加肩键的聊天快捷键也会停用（默认 ZR，随 GU 肩键设置交换），聊天仍可通过原版菜单或触屏打开。

猎人笔记的「武器操作指南」在 GU 武器的原有风格之后列出已安装的极之型手册。暂停菜单的「操作手册」中按确认键打开操作指南，扩展武器的手册接在 GU 武器之后。方向键左右翻页、上下切换武器，取消键返回。手册使用简体中文，可以在装备该风格之前查阅。

手册是风格插件的可选项。风格登记成功后可调用 `mhgu_sdk::weapon::style::manual::bind(id, include_str!("manual.txt"))`。UTF-8 文件用空行分页。操作页首行为标题，以下每行用一个制表符分隔操作与招式，最多九行。说明页支持 GU 的 `<ICON>`、`<SIZE>` 和 `<COL>` 标记。两种页面均可写 `{X}`、`{A}`、`{B}`、`{Y}`、`{R}`、`{摇杆}` 显示原版按键图标。

## 扩展装备

运行时的武器模块管理装备定义、等级表、库存、模型和装备组合，子模块负责风格注册和动作钩子。[武器模块](src/weapon/mod.rs) [风格子模块](src/weapon/style/mod.rs)

在道具箱首页，选中原版「更改･出售装备」下方的「扩展装备箱」，按 A 进入，按 B 返回首页并保留该项焦点。展开原版首页子菜单时，扩展装备箱仍显示在首页背景中。进入后由 GU 的「更换装备」控制器管理 10 × 10 图标格、光标、肩键翻页、排序确认、换装提示和音效。SDK 提供格子记录、已装备标记、武器图标和强化数值，换装写入 SDK 库存。排序只调整本次打开的扩展箱顺序。在剑士与射手之间切换时，确认框会提示可能卸下防具。第一格起显示已取得的扩展装备。要切回原版武器，在原版装备箱确认装备一把 GU 武器。选中实例时，原版装备详情面板显示当前和候选武器的数值。扩展装备的技能比较页待接入。两个装备格界面的 Switch 入口及离线回归见[扩展装备箱故障排查](../../docs/weapon-style-troubleshooting.md#扩展装备箱入口)。

[武器注册器](../../crates/mhgu-sdk/src/weapon/registry.rs)提供武器定义、发放、强化和查询接口。角色最多持有 128 个扩展武器实例，允许同时持有同一武器的多个实例。当前整合包包含六个原生武器极之型，扩展装备页显示通过内容插件发放、商店购买或工房制造取得的实例。强化等级由 SDK 持久化，内容插件负责登记配方和实现各级效果。

任务中装备扩展武器时，SDK 会跳过只包含回退武器专用槽的 HUD 布局绘制。生命值、斩味和狩技等共用界面继续由 GU 绘制。扩展武器可通过 `weapon::style::hud::bind_meter` 在斩味旁显示自己的资源槽，SDK 在 `hud0.gui` 的主组下创建 GU 多边形及可选的闪光贴图，图元随任务布局回收。武器也可提供整套 FZ 图集帧，由原生贴图对象绘制槽框、图标、准星和游标。临时提示从同一个回调读取，用 `hud0.gui` 原生文字和条形图元在屏幕中央显示。斗技大会等使用原版固定装备时，GU 会照常显示该装备的武器槽。

装备模型在原生武器部件绑定时由 SDK 解析。扩展武器可在注册后调用 `weapon::style::part_motion::bind` 登记主部件的动作库和选片函数。SDK 在 GU 部件更新入口应用挂点矩阵并采样注册轨道。片段有独立的循环终点时按猎人的帧增量推进。内容插件可通过 `part_motion::begin_motion` 为本地或队友登记换招时的部件重播和起播姿势混合。状态栏、装备资料和装备组合按装备 ID 找到名称，风格栏按类型找到风格。查看方缺少对应装备时显示原版资料。

原版装备和组合仍可在移除模组后直接读取。SDK 将扩展武器实例、强化、当前选择和装备组合关联保存在角色槽侧车中。组合关联使用原版记录指纹，应用时缺少武器插件或指纹变化会沿用原版组合。装备箱、队友资料和装备组合回退可用 [离线回放](../great-sword-extreme/tests/verify_menu.py) 核对。

## 商店与工房

进入武器商店的购买武器或工房的武器生产，原版类别之后按每页 7 条继续排列注册类型，按左右键循环翻页，也可从最后一个原版类别向下进入注册类型。第一页向前翻会到包含扩展类别的最后一页。选择对应名称和图标，例如「磁斩锤」。A 打开商品列表，方向键选择装备，A 确认，B 返回。工房生产沿用原版材料面板。首页的「扩展装备强化」位于「装备强化」和「装饰品」之间。GU 强化页从扩展装备格选择实例，显示材料、费用及前后数值。确认后更新该实例，未装备的武器可在成功提示后选择装备。列表中的名称、图标和等级数值都从对应装备读取。

扩展商品通过 GU 商店和工房的原版入口打开同一套列表，由 GU 处理商品翻页、预览操作、退出、确认框及成功音效。SDK 为这些控制器提供商品和配方，为预览提供注册模型。GU 扣除钱包里的金钱和原版材料，先用随身道具袋，再用道具箱。购买、制造或强化成功后，原版确认框询问是否立即装备。选择「是」时装备这次交易得到的扩展实例，选择「否」时保留在扩展装备箱。扩展装备箱满时仍可强化已有武器。

## 猎人资料与公会卡片

能力值、装备一览和装备详情使用注册武器的名称、强化等级、图标和属性。队友资料和模型通过 GU 的房间装备包取得扩展装备 ID 和强化等级。双方需要安装本版 SDK 及相同的武器插件。接收端缺少对应注册装备时沿用原版资料和模型。

自己的公会卡片随 GU 刷新装备时保存扩展武器快照。装备页和封面展示读取该快照。武器使用情况把注册的武器类型依次排在 GU 原版栏目之后。所有列沿同一条基线等距排列，在原版绘图区内居中，图标和柱宽随列数缩放。左右仍切换综合、村庄、集会所和斗技大会。扩展武器的次数按类型独立记录，GU 判定使用固定装备的斗技任务仍按原版计数。猎人生活日记保留原版任务、日期与滚动列表，在对应新记录上补充扩展武器类型，每累计 100 次会在该条记录标注里程碑。

交换公会卡片时使用 GU 原版内容。收到卡片的扩展快照、统计和日记没有同步。

## 角色存档

GU 确认角色保存成功后，SDK 将风格、扩展库存、强化等级和公会卡片的扩展资料写入 `savedata:/mhgu-sdk-<角色槽>.json`。每个角色管理一份，例如第一个角色用 `mhgu-sdk-0.json`。同名 `.tmp` 仅用于写入期间替换文件。原版角色存档仍保存金钱和材料。若在 GU 保存成功后、扩展资料写入前退出，两边可能相差最后一笔交易。

新版从单文件读取。旧版轮换文件和交易日志留在原处，首次使用新版时从空的扩展资料开始。

JSON 版本 1 包含 `slot` 和 `data`。`weapons` 按 GU 武器编号记录风格，`equipment_sets` 记录组合的风格 ID、武器编号和指纹。`inventory.instances` 按实例 ID 记录装备定义编号与强化级别，`inventory.equipped` 记录当前实例，`inventory.sets` 按组合槽保存实例 ID 和原版组合指纹。`guild_card` 保存装备快照、武器类型使用次数和与原版日记条目关联的扩展资料。缺少该字段时从空白记录开始。旧的 `custom_weapons` 启用标记会被忽略。

| 风格 | GU 武器编号 | 自定义风格 ID |
| --- | --- | --- |
| 极之型大剑 | `0` | `10` |
| 极之型双剑 | `11` | `11` |
| 极之型太刀 | `7` | `12` |
| 极之型斩斧F | `8` | `13` |
| 极之型单手剑 | `1` | `14` |
| 极之型铳枪 | `9` | `15` |

通过 [SDK 风格注册表](../../crates/mhgu-sdk/src/weapon/style/registry.rs) 声明常驻 `static Style`，填入角色存档和联机共用的全局唯一编号（10–65535）、GU 武器类型、动作及回调。内容插件在 Forge 入口调用 `registry::when_ready`，在回调中使用 `registry.register(&STYLE, name, description)` 登记一次。编号冲突返回 `Conflict`，保留先注册的声明。用 `registry.selected(weapon)` 查询启用的自定义编号，沿用原版时返回 `None`。更新时将 SDK 和武器 NRO 一起替换。

风格注册服务同时提供攻击提交与格挡结果。GU 从武器动作组派发已登记的 `0x8000..0x80ff` 槽位。风格根据 GU 已接受的拔刀或切招请求选择招式，并自行定义动作、派生窗口和格挡规则。注册器负责大剑切招、狩技接续、下一击强化与格挡收尾的原生对接。切出风格时用空输入通知控制器，actor 为 0 表示旧猎人已失效。

本地任务猎人使用角色装备记录时，运行时优先派发已装备的扩展武器风格，过滤回退武器的原生命令和动作槽。GU 仍处理公共动作与狩技。固定配装的斗技场等模式按 GU 分配的装备记录派发。扩展武器须实现自己的武器输入与私有动作，才能在任务中出招。[扩展武器控制回放](../great-sword-extreme/tests/verify_menu.py)

联机由 [multiplayer 模块](src/weapon/style/multiplayer.rs) 转接 GU 的 `netPlAction` 收发、远端风格查找、私有动作与逐帧观察派发。风格注册成功后通过 [`remote::bind_playback`](../../crates/mhgu-sdk/src/weapon/style/remote.rs) 登记一次回放描述符。注册器按当前名册和远端猎人的装备武器选择回放。每把武器负责自己的动作、附加状态值与效果清理。动作包格式沿用现有 GU 布局。运行时与武器 NRO 使用同次构建的成品。

扩展武器通过装备资料包识别实际武器类型和装备 ID。其三位可选动作状态值和存在标记放在 `mPlAttr` 的位 22–25，确保回退武器仍按原版解读位 16–19，与收刀标记的位 20–21 也互不重叠。

绑定 `remote::bind_position_state` 的扩展武器在私有动作包的位 26–31 携带动作序号。GU `200438` 的周期位置包在 `mPlAttr` 的位 8–13、16–23、24–26、27 分别携带序号、私有动作 ID、状态值和存在标记。确认收到对应动作后，注册器再派发附加动作状态。跨动作的武器状态用位 28–29 携带状态值，位 30 表示存在，位 0–3 和 14–15 携带更新序号。每次武器状态变化推进一次序号，接收端丢弃旧值和重复值。两个字段可随同一包发送，GU `1FFFF4` 继续更新位置与朝向。[位置包实现](src/weapon/style/multiplayer/position.rs)

[风格资料同步](src/weapon/profile.rs)通过 `netPlData::mAttr` 携带完整的注册编号，保留 GU 的装备风格字节和回包请求位。注册器核对接收槽位、当前装备记录和武器类型后再显示名称。替换装备资料或离开房间会清除对应记录。

扩展武器的怪物接触走 GU `1F00F8` 和 `1F51F4` 的 `netEmUniqueData`，使用 `CB120` 保留的类型 9。原生头部保存 `em_set_id` 和 `rev_count`，资料区带有 SDK 标识、风格、事件序号、区域、部位、受击形状行和骨骼局部偏移。注册器通过 GU 的接收槽验证当前队友装备，在接收者区域解析同一次生成的怪物。[怪物接触包](src/weapon/style/multiplayer/target.rs)

带冲刺收刀的风格通过 `remote::bind_sheathe` 登记冲刺动作与两种收刀片段。双方使用本版时，队友可直接从收刀包确定片段。未携带收刀标记的旧版动作包沿用接收端的动作历史。[冲刺收刀联机回放](tests/verify_sheathe_multiplayer.py)覆盖六种极之型、错过冲刺或刹停、两名队友以及收刀结束。

`art_slots` 指定狩技槽位数（0–3），装备、充能和发动由 GU 处理。扩展武器在原版「切换风格」页确认已装备风格后，进入 GU 狩技页。换装时，运行时让 GU 按当前武器清理不兼容的狩技，在风格槽位额度内保留通用狩技。狩技仍由 GU 保存。扩展武器和原版武器的风格页统一由[风格注册运行时](src/weapon/style/menu.rs)接入。`independent` 使 GU 的固定长度风格表使用索引 0，并停用勇气槽。仅替换动作资源的风格可以省略控制器。

发布版首次请求某把武器的私有路径时，注册器先通过 GU `BCAD18` 读取 `common.arc`，再读取对应武器 ARC。两者保留在资源缓存中。GU 的 `B39F58` 按归档顺序加载依赖，供当前猎人和队友后续的原生路径请求复用。详见[打包回归](../../tools/tests/verify_packed_release.py)。

极之型武器使用同一个[预读入口](../../crates/mhgu-sdk/src/weapon/style/preload.rs)。GU `29B7D4` 完成任务初始化后，注册器只调用本地猎人当前风格的预读回调。男女模型共用的三组动作库和私有命中形状同步准备，供入场后的首次攻击使用。PEL、SRQR 和 HUD TEX 交给 GU 资源加载线程，原生资源标记完成后才能使用。动作库在实际播放时绑定到猎人。

武器插件通过 [ParticleModelV1](../../crates/mhgu-sdk/src/weapon/style/particle.rs) 登记模型粒子绘制回调。注册器初始化共用的 FZ 模型粒子渲染器，负责保存和恢复 GU 的绘制状态，并派发粒子释放回调。

构建注册器与武器模组后，用装有 Unicorn 的 Python 运行 `plugins/great-sword-extreme/tests/verify_style.py` 和 `verify_menu.py`。后者回放装备箱选择、角色槽隔离、GU 保存失败、单文件重载、装备组合保存和应用、概要及详情、个人与队友状态及装备资料收发。使用内存文件、渲染替身和传输替身。[交易与存档回放](../great-sword-extreme/tests/verify_trade.py)执行成品 NRO 的工房、商店和保存钩子，使用 GU 原生金额及扣材料函数验证购买、制造、强化、容量、材料扣除失败和强化等级重载。

按[开发指引](../../docs/development.md#验证范围)打包全部武器后，运行 `python3 plugins/mhgu-sdk-runtime/tests/verify_weapon_styles.py`。该入口覆盖 SDK 最后启动、猎人笔记与暂停菜单中的手册显示和返回，以及各武器的任务预读与粒子资源。手册文字随武器 NRO 更新。

内容插件可通过 [StyleRulesV2](../../crates/mhgu-sdk/src/weapon/style/rules.rs) 登记格挡半角、公共动作结束条件、弹刀与镜头回调。普通任务镜头在 GU `255CC` 的手动镜头输入前读取风格的水平视角，在 `26E64` 的原生碰撞前读取构图和视野角。视野角供当前镜头投影与绘制使用，下一次 `21A90` 更新原版镜头前恢复基准。垂直震动在 `898AC0` 的视图更新中计算。注册器在 GU 近战解算后按猎人、动作槽和刀身的打击序号匹配 `Attack::DEFLECTABLE` 或 `Strike::deflectable` 标记的命中，并用 GU 的斩味修正、心眼与相关豁免完成判定。动作控制器通过 `mhgu::BladeDeflectionV1` 取得结果。

`melee::bind_strike_contact` 在 GU `17885C` 结算会心后通知本地独立武器，提供原始动作值、生成时的加成和实际会心倍率。场景接触由 `bind_world_strike_power` 从风格的接触池取得已登记的动作值。磁斩锤用这些值计算主攻击和强化磁冲击追加命中的磁力回充与磁气积累。独立近战可登记倒地反应。运行时将确认的本地命中交给 `9A828` 在原生伤害结算时处理，地面倒地使用骑乘成功反应 33，保留原版死亡和异常状态优先级。磁缚终结先核对怪物出生实例和出招者，存在有效的正数标记行号时只让该受击行参与这次碰撞。GU 在 `9D67C` 清空损伤数据时一并清除该怪物待处理的倒地请求。[战斗回放](../magnet-spike/tests/verify_battle.py)
