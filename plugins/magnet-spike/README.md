# 极之型磁斩锤

试制磁斩锤是用于验证 MHGU 1.4 装备注册、制造和购买的测试装备。武器类型与极之型风格的编号均为 16，具体装备编号为 `0x1001`。依赖同次构建的 [MHGU SDK 运行时](../mhgu-sdk-runtime/README.md)。

- 武器商店的购买武器或工房的武器生产，在原版类别之后翻到下一页，或从最后一个原版武器类别向下选择「磁斩锤」，再选择「试制磁斩锤」。购买价 **100z**，制造费 **0z**，材料为 **回复药 ×1**（GU 道具 9）。
- 道具箱首页打开「扩展装备箱」，使用 GU 的「更换装备」界面翻页和确认装备。买入和制造分别增加一个实例。交易成功后会播放 GU 原版音效，并可在原版确认框直接装备试制磁斩锤。原版「切换风格」页面显示该类型的极之型。按 A 确认可进入原版狩技页，从通用狩技中装备最多三个。
- 自己的公会卡片会在「武器使用情况」图表的原版栏目后显示磁斩锤及其独立使用次数。猎人生活日记会在新产生的相应任务记录中标注磁斩锤。
- Lv.1 使用验证用数值，攻击 100、会心 0%、无属性、无孔，斩味表 10、斩味等级 0。基础动作和连段会播放猎人动画及对应的磁斩锤部件动画。攻击判定、FZ 专用部件挂接、磁力招式与 HUD、专用音效特效和联机动作播放待接入。

| 当前操作 | 对应动作 |
| --- | --- |
| 收刀时按 X 或 X+A | 分别以斩击、打击形态拔刀。 |
| 持刀时按 GU 特殊攻击键（默认踢键） | 按当前形态播放切换动作。 |
| 持刀时按 X、A 或 X+A | 按形态起手，部分派生可在前一段动作中预输入。 |
| 动作允许翻滚时按 B | 交由 GU 公共翻滚动作处理。 |

## 模型和图标来源

MHF-Z 的 `mhfdat.bin` 近战装备记录 16881 指向模型 6451，类别为 13。网格、骨骼和原色贴图来自 `dat/extend/wk000.abn` 的 `wk451.bin`。转换器使用 GU 材质模板生成 MRL，连同 MOD 和 TEX 写入 `arc/frontier/magnet_spike.arc`。GU 注册资源名为 `weapon\frontier\magnet_spike\wk451`。

打包时从本地 MHF-Z 的 `dat/mhf.bin` 读取第 54 号 PNG 条目（从零计数），原样取出左上角坐标为 `(192, 896)` 的 64×64 磁斩锤图标。生成的 `GUI/frontier_magnet_spike/icon.tex` 和 NRO、模型 ARC 一起安装。

磁斩锤的 FZ 武器编号为 13。打包时用 `magnet-spike-battle` 将 `motion/w13.mot` 的猎人动作和 `motion/w13w.mot` 的部件动作写入同一个武器 ARC。部件动作使用 `wk451.bin` 的骨架。控制器读取打包时生成的 `magnet_spike.fmsa`，其中包括原始动作、形态分类和判定表。目前运行时使用动作和形态数据。[转换器命令](../../tools/mhfz2mhgu/README.md)

## 构建与验证

从仓库根目录运行以下命令。

```sh
python3 plugins/mhgu-sdk-runtime/package.py
python3 plugins/magnet-spike/package.py "$MHFZ_DAT" "$MHGU_ROMFS"
python3 plugins/magnet-spike/tests/verify_magnet_spike.py
python3 plugins/magnet-spike/tests/verify_battle.py
python3 tools/package_weapon_styles.py --include-magnet-spike
python3 tools/tests/verify_packed_release.py --include-magnet-spike
```

成品回放覆盖两种插件加载顺序，执行 GU 商店和工房的原版入口与交易控制器，并核对成功音效指令、立即装备、预览初始化、预览方向输入、装备数值和模型绑定。游戏内的实际音效和 3D 画面需要实机确认。安装时从整合包取出 `mhgu-sdk/` 和 `magnet-spike/`，保留各自的目录结构。

打包回归检查猎人动作组 0、2、4 与武器部件动作组 0、1、2、4 的 LMT 目录。部件动作组 1 只含 0、1、2 三个槽，供 FZ `8121E3EA` 选择收刀及两种持刀形态的常驻姿势。

战斗回放从 GU 猎人派发和原生命令解释器进入，检查两种拔刀、跨片段预输入、斩击与打击起手、B 翻滚、回退武器命令隔离及任务预读。回放替换动画播放和场景层边界，读取成品 ARC 的 LMT 目录核对动作槽绑定、部件采样帧与循环起点。游戏内动作外观待实机确认。[战斗回放](tests/verify_battle.py)

## 战斗入口核对

| FZ Vita 入口 | 源数据与观察 |
| --- | --- |
| `8121E646`、`8121E6F8` | 两个原生拔刀入口按 `824F0AD8` 的条件筛选命令。后者将命令 2／22、4、9 分别派发到状态 78、79、112。状态 78 使用片段 1440→1049，状态 79 使用 1023→1413。 |
| `8121E820`、`824F0C28` | 持刀起手按形态读取列。命令 2 对应状态 0／18，命令 3 对应 6／32，命令 4 对应 2／26。磁力相关起手另外检查目标和资源。 |
| `8122482C`、`82B3AED8` | 25 个命令按源优先级筛选。`8122570A` 再处理 202–208 等虚拟目标，将它们解析到公共动作或具体武器状态。 |
| `8121DA12`、PC `mhfdat.bin` `0xb90` | 三个类型列表分别标记斩击、打击和沿用上一形态的状态。GU 控制器在进入私有动作时使用这张分类表。 |
| `8121E3EA`、`8121E57E`、`81731BF4` | 根据猎人片段及收拔刀、形态判断选择部件轨道。共有片段 1435 的猎人轨道与部件轨道分别有 89、91 帧，循环起点均为 52。SDK 在 GU `3078B8` 更新挂点后经 `954640` 提交部件轨道。 |
| `81225C60`、`81225C8A` | 动作事件 3 和 4 分别选择判定族 120 和 121。族 120 的选择器 1 和 3 各包含两条部件形状，分别锚定到骨骼 5 和 7。 |
