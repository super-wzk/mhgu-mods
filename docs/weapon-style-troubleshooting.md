# 武器风格常见故障与排查

先确认复现用的武器、风格、动作状态和输入顺序。对照安装包及 Forge 日志，再从最早出现偏差的引擎步骤往下查。以下案例中的槽号和地址对应当前仓库使用的 GU 1.4 与 FZ 数据。

各武器的当前行为、源实现和回放入口见[极之型武器实现与回归](weapon-style-implementation.md)。构建安装及离线依赖见[开发指引](development.md)。

## 扩展装备箱入口

首页能看到「扩展装备箱」，移到该项却消失时，核对运行时版本和首页实际行数。GU 的 `714598` 在光标中记录 8 或 9 个原版命令，面板的 `+92` 始终是 9 个控件的容量。SDK 将逻辑行号映射到可见控件，由 `5C56E8` 定位高亮。首页移动光标时只更新高亮，滚动窗口才换行文案。原版子菜单展开时，面板仍从 `5C1FA4` 更新首页和子菜单。SDK 保留原版更新，再补画首页扩展行。

A 进入扩展装备箱后，GU 面板 2 使用模式 6，经 `5B68FC → 5B91E0` 绘制装备格。SDK 提供扩展实例的图标和详情，GU 负责定位光标。B 返回首页时保留扩展行焦点。[成品回放](../plugins/great-sword-extreme/tests/verify_menu.py)核对实际可见行、高亮位置、停留时的文字写入、空箱、首格装备、第二页格子、格内光标坐标及通过原版装备箱切回 GU 武器。

购买或生产武器时，各注册武器类型以自身名称和图标接在最后一个原版类别下方。类别按每页 7 条排列，原版末页有空位时先填满，满页后继续到下一页。页码由 `593514` 调用原生指示器显示，页数按原版和注册类别的总数计算，第一页往前翻回最后一页。回到原版页时由设施控制器更新原版行数据。若 Forge 日志已显示内容插件载入但类别不可见，检查 `cUIOShopTopPanel` 虚表的更新入口 `592FE0`。原版从这里尾跳到内部绘制函数 `592FFC`。交易回放通过 GU 的面板虚表核对原版满页、原版未满页、多个注册页、页码、选择及返回。[交易回放](../plugins/great-sword-extreme/tests/verify_trade.py)

SDK 从原生类别面板的光标和文案表确认所属设施，首轮绘制即可获取注册类别。Forge 日志中的 `Magnet Spike: weapon, icon and trade offers registered` 确认磁斩锤注册完成，`Shop weapon categories` 和 `Smith weapon categories` 分别记录是否进入输入或绘制入口、存档是否可用以及注册的类别数。

类别出现但图标空白时，检查插件是否随 NRO 安装了 64×64 的 TEX。SDK 在 `56E6A8` 给原生精灵绑定独立贴图，并在控件重新绘制原版图标时恢复其原版图集。[磁斩锤图标回放](../plugins/magnet-spike/tests/verify_magnet_spike.py)

扩展商品选中后使用 GU 的武器商店控制器 `6EA28C` 和工房控制器 `6F31D8`。SDK 投影当前页的商品和配方，原版交易提交 `6ED128` 和 `6FB224 → 6FBCFC` 扣除款项和材料。交易行提供零类别、零装备编号，GU 的原版发放入口 `1421B4` 因此直接返回。扣款和扣料确认成功后，SDK 分配或强化实例。原版成功音效走 `54F260`，是否装备由原版确认框处理，并在 `6ED344` 或 `6FBF4C` 选择 SDK 实例。

商店预览初始化和输入走 `6ED600`，工房走 `6FC2C8` 和 `6FDA94`。现有 GU 装备的姿势参数仅在预览调用期间提供，部件绑定读取注册模型。离线回放执行原版控制器、扣料、预览参数和光标处理，并记录音效调用。实机需确认音效播放及预览画面。

扩展武器详情数值不符时，先核对装备 ID 与当前强化行。GU 的 `DEE34` 分别读取攻击、会心、斩味等级及双属性，`DE16C` 读取武器固有技能。模型异常时核对注册的 ARC、MOD、同名 MRL 和贴图。GU 通过 `289670 → 307F18` 的主武器部件绑定模型。[成品磁斩锤回放](../plugins/magnet-spike/tests/verify_magnet_spike.py)

扩展武器确认换装后仍带着旧武器专属狩技时，核对 `286318 → 277848` 的武器编号。狩技兼容性用注册的武器类型确认，GU 保留通用狩技。风格页确认已装备风格时，`5490FC` 进入原生狩技流程的阶段 5，阶段 6 使用同一兼容性检查确认所选狩技。槽位数由 `2778AC` 读取所选武器的风格登记，磁斩锤极之型为三个槽。[装备箱回放](../plugins/great-sword-extreme/tests/verify_menu.py)

## 猎人资料、公会卡片和生活日记

名称、图标和详情分别从能力值 `62E258`、装备一览 `630268`、互动装备列表 `589D50 → 589C74` 和详情 `57F468` 更新。暂停菜单的 `674880` 把原生装备行与临时属性副本分开传入，详情按装备行识别武器。图标使用武器类型和 GU 稀有度颜色，控件回到原版装备时在 `546F84` 恢复原图集。联机时检查 `202894 → 274400` 是否将扩展装备 ID、强化等级和原版类别匹配到实际队员槽。

公会卡片用 `166A30` 核对卡片主人。装备快照来自 GU 刷新入口 `1623B4`。封面模型经过 `15FADC → 2744BC → 307F18`，主武器部件由 `303790` 更新。结算统计由 `38EAE4` 判定任务分类，扩展次数写到当前角色的 A/B JSON。猎人生活日记在 GU `162758` 接收原版条目后保存扩展资料，再从 `5A7B00` 补充当前可见行。原版武器已经累计的次数无法反推为扩展武器。

使用统计图 `5A6CB4` 中的扩展列若偏到页签附近，检查 `54501C` 是否把模板 29 实例挂到 `guildcard_down.gui` 的柱列容器 `Null_bar`（组 `0x24`），并让它使用原版末列的动画序列。原版使用次数按武器索引读取，布局按实际列坐标排序。回放覆盖一列、两列、返回原版图表时的顺序、间距、基线和图标比例。[猎人资料和公会卡片回放](../plugins/great-sword-extreme/tests/verify_menu.py)

## 构建和启动

| 现象 | 已有案例与排查方法 |
| --- | --- |
| IDE 或命令行报 `.json target specs require -Zjson-target-spec` | 从插件目录运行构建，确认 Cargo 读到了该插件的 `.cargo/config.toml` 和 `[unstable] json-target-spec`，并使用对应 nightly。 |
| 代码已改，回放或游戏里还是旧行为 | 比对插件根目录、`dist` 及游戏模组目录里的 NRO 哈希。离线脚本通常加载 `dist` 中的成品。改了动作程序、音库或粒子等资源时，重新打包相关插件并同步配套资源。 |
| 暂停菜单操作手册返回时或启动期间崩溃 | 核对风格注册器 NRO 及故障栈是否经过 GU `65F7A4`。该入口第二条指令有 PC 相对取值，Forge 的旧 trampoline 复制后会读错位置。当前关闭钩子直接走原生对话框关闭和移除入口。用[共用武器验收](../plugins/mhgu-sdk-runtime/tests/verify_weapon_styles.py)检查无对话框、已有对话框、两个手册入口和返回。 |

## 命中和骑乘积蓄

- **普通空舞出现骑乘值。** GU 的双剑 HDP 行 61、62 同时带空中斩击形状和骑乘属性。注册器在本次 HDP 行副本上处理 `Attack::NO_MOUNT`，先清除骑乘属性再调用 GU 构造，形状沿用原模板。普通空舞连斩与命中后按 A 的终结使用无骑乘设置。跳下台阶等普通滞空按 X 是单独的终结动作，保留骑乘值。普通空舞状态里的 X 分支已移除。见[命中构造](../plugins/mhgu-sdk-runtime/src/weapon/style/attack.rs)和[双剑战斗控制](../plugins/dual-blades-extreme/src/battle.rs)。
- **选对模板，写回却未执行。** 跟到虚表调用点核对参数。双剑 `11BAD38` 是 `2B76CC` 调用的命中调整虚函数，实参为猎人、接触对象、HDP 行指针和标志。此前把第三个实参当作攻击类别比较，导致处理提前返回。另一个武器修正的虚表入口参数不同，应逐个确认。
- **拔刀斩延迟或命中阶段不对。** 区分事件到达帧、模板自带的延迟以及本次有效区间。事件触发后只传入剩余延迟，跨帧时扣掉已经过去的有效时间。大剑后退、横扫或蓄力接出的攻击应按当前片段与招式选择行。
- **拔刀攻击吃不到拔刀术。** 从拔刀起手追到释放动作和命中构造。大剑与斩斧的拔刀蓄力通过 GU `2AB670` 为本次释放保留拔刀标记，普通切招会清掉该标记。命中构造须启用会心计算。拔刀术【力】还要求 HDP 第 34 字节为负的条件眩晕值，具体数值按 GU 对应武器的命中模板核对。回放时分别核对拔刀、持刀与后续连段，并单独验证会心和眩晕。见[大剑回放](../plugins/great-sword-extreme/tests/verify_style.py)及[双剑、片手、斩斧和铳枪回放](../plugins/mhgu-sdk-runtime/tests/verify_draw_attacks.py)。
- **加成未消费、同一招多次扣斩味、精准防御数值偏差。** 兽魂附身在首个有效大剑命中构造时进入原生修正，起手或空阶段保留。多段独立判定逐段声明斩味策略。精准防御按碰撞确认、受击反应、斩味和无敌计时分别对照，避免从看见回正动作推断所有伤害处理。见[大剑原生修正](../plugins/mhgu-sdk-runtime/src/weapon/style/routes.rs)、[防御接入](../plugins/mhgu-sdk-runtime/src/weapon/style/guard.rs)和[大剑命中数据](../plugins/great-sword-extreme/src/combat.rs)。
- **精准防御有动作却挡不住攻击。** 分开检查 GP 窗口、来袭角、GU 命中标记和防御强化资格。注册器使用风格声明的半角补判时仍遵守 GU 的攻击排除规则。对需要防御强化的攻击，分别用有技能和无技能的装备验证。见[防御接入](../plugins/mhgu-sdk-runtime/src/weapon/style/guard.rs)。
- **大剑精防成功却挡不住怪物推进。** 检查成功后保护时间、是否已接反击、怪物是否在地面以及是正撞还是擦边。联机先确认负责怪物位移的一端装了配套大剑插件，再核对 `netPlAction` 上精防成功标记及对应队员槽。见[位移阻挡](../plugins/great-sword-extreme/src/guard_body.rs)和[联机回放](../plugins/mhgu-sdk-runtime/tests/verify_gs_db_multiplayer.py)。

## 声音和渲染

铳枪曾出现点火动作和斩味加成均正常、枪刃却没有光焰的情况。`1427/1428` 没有相应的片段粒子记录。排查类似问题时，还要查原版武器状态更新及动作事件里创建的特效对象。铳枪回放分别检查起手两轮、加成生效及加成后的首次突刺，核对每次提交的 PEL 选择器、跟随关节以及成品 EFL 的实际颜色和透明度。见[铳枪离线回放](../plugins/gunlance-extreme/tests/verify_port.py)。

有粒子提交却看不到主光，或主光与刀刃分离时，核对可见网格实际受哪个关节驱动、挂点是否已转换到该关节的局部坐标，以及光效网格的轴心和范围。铳枪将 FZ 的主光和光晕挂点映射到 GU 当前型号的刃轴，再通过逆绑定矩阵挂到 GU `455EB8` 选定的枪管关节。FZ `8171A364` 保持枪刃轴向，只绕该轴转动主光平面。回放固定武器根节点，单独改变枪管与相机，检查实际绘制坐标和朝向，并与 Vita ELF 对照缩放和颜色曲线。点火音也需检查状态和特效回调。铳枪的生效音由 FZ `81FC9E0A` 发出，补接后在 GU 回放中检查成品音库的请求是否在生效时入队。
